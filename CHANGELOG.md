# Changelog

## Unreleased

- **`amness serve`: Amness as a service.** The app in any browser (your phone on the home network too) and an HTTP API (`/v1`, JSON and Server-Sent Events, OpenAPI at `/v1/openapi.json`): start sessions, send messages (with `wait`), read the transcript, answer approvals, run slash commands, stream events. Sessions are the terminal app's own, so everything works the same. A saved token (`amness serve token`), this computer only by default; `--host 0.0.0.0` for your network, `--tls-cert/--tls-key`, `--root` folders, Host and Origin checks, a request log. `AmnessClient` in the library (`run` answers dialogs with a callback). See docs/api.md.
- **MCP servers everywhere, saved like in Claude Code.** `amness mcp add|list|get|remove|enable|disable` and `/mcp` save servers for this project (`.amness/settings.local.json`, kept out of git), for the team (`.mcp.json`, Claude Code's file, so existing ones just work) or for all your projects (`~/.amness/config.json`). They start in the terminal, the desktop app, `amness run` (`--mcp-config`, `--strict-mcp-config`, `--no-mcp`) and in editors over ACP (the editor's own servers too). Remote servers over Streamable HTTP (protocol 2026-07-28 with its required headers, and the older session and HTTP+SSE versions), static headers and `headersHelper`, `${VAR:-default}` values. A project's `.mcp.json` starts only after you trust the project, your provider keys never go to a remote server, and the agent may not write `.mcp.json`. See docs/mcp.md.
- **MCP tools cannot change behind your back.** Each tool's description and schema are remembered when a server first connects; a changed or new tool is held back until you approve it (the terminal and desktop show the old and new text; `/mcp approve`, `amness mcp approve`). Descriptions with signs of hidden instructions are flagged (`amness mcp check`). Results over 40,000 characters go to `.amness/mcp-output/` and the model gets the start and the path.
- **Fixed: `amness doctor` failed careful models on "corrects a call after an error".** The check told the model, in a tool result, to store a different number than the one the user asked for. Current models such as Claude Sonnet 5.5 rightly refuse an instruction from a tool result and ask the user, so they were marked not fit for the main and edit jobs (and `--write` set them to the local tier). Now the error is a missing argument whose right value is in the user's request.

## 0.9.0 (2026-11-13)

- **Desktop: the window opens at once.** Amness now starts the window first and shows a start screen (the logo, the name, a moving line) while the agent loads, then fades into the app. Before, nothing showed until everything had loaded.
- **Desktop: easier to find your way.** The top bar has a search box, "Search or run a command" (Ctrl/Cmd K), clear icons instead of symbols, and a labelled Settings button. In Preferences, controls line up across rows and tabs, and folder lists are one tidy box.
- **Settings for this chat, this project or all your projects**, as in Claude Code. `.amness/settings.local.json` holds your settings for one project (kept out of git), `.amness/settings.json` the team's (used after you trust it; it cannot choose your provider or keys or loosen safety), `~/.amness/config.json` yours for every project. A setting about the code is saved for this project, a setting about you for all projects. `/set … --chat|--project|--team|--user`, the Apply choices in `/settings` and **Save for** in Preferences choose another place, and every setting shows where its value comes from. The agent cannot edit these files.
- **Fixed (desktop):** a long choice in Preferences no longer squeezes its description into a thin column.
- **Retro theme.** `/theme retro` in the terminal, and **Retro** under Preferences > Appearance in the desktop app: blue panels, cyan double frames, yellow highlights, and a key bar at the bottom of the terminal. It is a choice on every system. The default stays Aurora, on Windows too.
- **Provider icons that look like their brand.** Claude keeps ✻. OpenAI models now show ❁ (a blossom, like the OpenAI mark), and local models show ⌂ (they run at home, on your machine). Before, these were ◈ and ⬢.
- **A No to project hooks or plugins is remembered.** Before, Amness asked again in every new chat, and the desktop app starts one for each chat. Now it asks again only when those files change. `/trust` (or Settings > Folders and trust) shows your answers and asks again.
- **Fixed: the desktop app reopened a folder you did not trust.** A folder you open goes into the recent projects. After a No it stayed there, so the next start opened it, asked again and closed the window. Now a No removes it, and the app never starts in a folder you did not trust.

## 0.8.1 (2026-11-12)

- **A local model that only looks now starts writing.** On a task that asks for a new program, a local model looked at the same small files again and again (`read_file`, `xxd`, `od`) and never wrote anything. Three causes are fixed. The prompts now say that a new program starts with a first working version that is then improved. With a local-tier model outside the chat, the agent is told at steps 6 and 10, if it has not edited a file yet, to write a first version and improve it (the write-first note, part of the `wrapup` guard). And reading through `sh` (`cat`, `od`, `grep` and similar) now counts as reading, so the "only reading" note can fire. Measured on 2026-11-12 on the Terminal-Bench task `cobol-modernization`: with the note the agent wrote the program and passed; with a note of the same length without the advice it edited nothing. One run each.
- **Fixed: the stagnation guard stopped runs that were checking their work.** Comparing outputs with `diff` or `cmp` now counts as a check, and a check that passes after a new edit counts as progress. Reading the same file again through another command no longer counts as new. When the checks pass after the latest edit, the stagnation note tells the agent to finish. Before, a run that had written a working program and was comparing its output with the original program's was stopped as making "no measurable progress".
- **Fixed:** the claims ledger refused a finish that said "it compiles" after a direct compiler run, because it knew only build tools such as `tsc`, `cargo` and `make`. Compilers count now too (`gcc`, `g++`, `clang`, `javac`, `rustc`, `coqc`, `cobc`, `pdflatex`, `cmake --build` and others). Found on a Terminal-Bench task, where the refusal cost two extra steps.

## 0.8.0 (2026-11-11)

- **Work on several things at once.** `/bg <task>` (terminal and desktop) runs a task in the background, in its own git worktree, while you keep working; you are told when it ends, and `/bg apply <n>` takes its changes. The desktop app keeps a chat working when you open another one or start a new one: the chat list shows which ones work or wait for you, each chat keeps its own provider and model, and a second chat on the same project gets its own worktree. `amness run --background` starts a run that keeps going after the command returns; `amness tasks` lists, shows, applies and drops them.
- **Two windows no longer overwrite each other's settings:** saving writes only the settings that window changed.

- **Models for jobs can be on any provider or saved server.** `/models explore server:lab`, `/models compact anthropic:claude-haiku-5-5`: a job's model is now a reference to any provider you are connected to or any saved server, each with its own key (a saved server's key is never sent anywhere else). Before, every job had to use the main provider. New jobs `approve` (the approval reviewer) and `quarantine` (the reader of untrusted content). A subagent file's `model:` key now works too: a job name or a reference. Same in the terminal, the desktop app and `amness run`.
- **`amness run` uses models per job.** It now reads `models`, `fallback` and `router` from the config (before, only the chat did), and has flags for one run: `--explore-model`, `--compact-model`, `--review-model`, `--cheap-model`, `--approve-model`, `--quarantine-model`, `--fallback`, `--router`, and `--subagents` for the `task` tool. The `--json` config line lists the jobs on other models (`roles`).
- **Broken tool calls are corrected instead of refused (new guard `argfix`).** Arguments that are almost JSON (trailing comma, single quotes, line breaks in a string, extra text, wrapped in `{"arguments": …}`), types that are clearly meant (`"12"` for a number, `"true"` for a boolean, one value for a list) and a tool name that can only mean one tool (`Read_File`) are fixed before the call runs, and the model is told what was corrected. A missing value is never guessed. Saves a round trip per mistake, which matters most on slow local models. Switch off with `/harness off argfix`. Not measured yet.
- **Each model keeps its own settings.** A model's window, profile (`toolChoice`, `thinkingBudget`, `keepThinking`, `request`) and tier now travel with the model. A job on another model is called with that model's settings, not the main model's; the handoff note is asked for in a size the compact model's own window can hold; a window learned from an error is remembered for the model that gave the error; the router no longer sends a step to a cheap model whose window cannot hold the conversation. With a fallback or the router, history is rewritten (the cheap context steps) only while a model that allows it is answering, so pairing Claude with a local model no longer switches the steps off for the local model. New profile field `tier` (`local`, `mid`, `frontier`; guessed when not set).
- **Evaluations with models per job.** A variant can put jobs on other models: `amness eval --variants full,full@explore=server:lab`. The report then shows tokens per solved task and waiting time per tier (local, mid, frontier), and each run counts `reread` (files read again after the context was trimmed or reset). The `amness run --json` config line has a `harnessCard` (the settings in seven layers: execution, tools, context, scheduling, observability, verification, governance) and the result line has `byModel` and `byTier` when more than one model was used.
- **A server that cuts the prompt without an error is noticed.** When a local server (Ollama) reports the same prompt size twice while the conversation keeps growing, Amness takes that as its real window, works inside it, and tells you once to raise the server's context length. For Ollama, the window is now read from the context the model was loaded with, not the model's maximum.
- **Tool calls written as text can be taken (`textToolCalls` in a model's profile).** Some local models write a call into their answer (`<tool_call>…</tool_call>`, `<function=…>`, `[TOOL_CALLS]`, `<|python_tag|>`, a JSON object) instead of sending it as a tool call, so it was lost and the agent was nudged. With `"textToolCalls": true` such a call runs when it names a real tool with valid arguments. Off by default.
- **A model's tier changes its prompt and tools (`tier`, `tools`, `prompt` in a model's profile).** `"tier": "local"` gives a weak model the short local prompt and the lean tool set even with a large window (before, only a window of 16,384 or less did). `"tools"` limits the tools a model is offered; `"prompt"` picks its system prompt. A guessed tier changes nothing. New eval variant `tier:local`. Not measured yet.
- **`amness doctor [model]` (and `/doctor`) checks a model before you give it a job.** About ten short requests with test tools: a typed call, two calls at once, a chain of three, `tool_choice: "required"`, calls written as text, recovery after an error, the stated window, and prefix-cache latency. It prints which jobs the model can take and suggests profile settings; `--write` saves them, and `/models` then warns when a job does not match.
- **Jobs on other models hand back when they fail.** An explorer or read-only subagent on another model that stops without finishing or returns nothing is now a `takeover`: the main agent is told to do that part itself, and after two failures the job runs on the main model. The explorer uses its own model's window, prompt and tool descriptions. New: **Explorer returns file ranges** (`exploreRanges`, checked against the files), `budgetLocalWeight` / `--local-weight` (local tokens count less against the cap), and `/tokens` per model. A local server now gets one request at a time by default.
- **Fixed tool list (`stableTools`).** With **Fixed tool list** in Settings (or `amness run --stable-tools`), a tool found with `tool_search` runs through `call_tool` (or by its name) instead of being added to the tool list, so the list stays the same and the prompt cache (or a local server's prefix cache) survives. Permissions, approvals and checks see the real tool. `amness doctor --write` now also saves a local server's measured `cacheFactor`, which prices cost-aware rewrites in time. Eval variant `tools:stable`. Not measured yet.
- **An advisor (`/models advisor`, `--advisor-model`).** The agent can consult a stronger model at a few moments. With a Claude main model and a Claude advisor, Amness uses Anthropic's advisor tool (the tool stays fixed for the conversation; `pause_turn` is resumed; the advisor's tokens are counted for it; a per-conversation cap). With any other pair, a generic advisor: an `advise` tool, plus advice before the first change, when stuck, and before finishing, from a short summary of the work, never the whole conversation. Not measured yet.
- **A recovery ladder (`ladder`, `--ladder`).** The main loop can run on several models, cheapest first. A risk score from the loop's own signals decides, in order: reflect, start again from a note, move up a model (which starts from the note, not the whole conversation), and step back down after a clean stretch. Eval variant `ladder:<model>+<model>`. Not measured yet.
- **Router:** the cheap model can no longer start subagents; when its step is redone by the strong model, the strong model sees its suggestion, and its tokens are counted (before, they were not). `Prices` can have a fixed cost per call for a local tier.
- **New guards `hollow` and `reread`.** `hollow` refuses a write or edit that would replace code with a placeholder line ("// ... rest of the code unchanged ..."). `reread` sends a local-tier model back once at its first finish to check each requirement of the task. Both not measured yet (`full-hollow`, `full-reread`).
- **A response schema is never sent together with tools to a local server** (it can stop tool calling entirely); you are told once.
- **`amness eval --builtin ladder`**: five levels of tool use; the report says which jobs a model qualifies for, and `--write-profile` saves it.
- **`amness tune` can try per-model settings:** `--text-tool-calls`, `--tier-local`, `--prompts`, `--tools` (one tool fewer at a time), and the new guards. Kept only when they hold on training and held-out tasks, and written only into that model's profile.
- **Eval variants `edit:whole-small` and `edit:delegate`** (edit-format experiments, not defaults).
- **Fixed:** a writing subagent asked for approval of its edits in a run without permission modes (evaluations, the library), where the main agent did not.
- **Fixed:** the handoff note written without the model (when the context is too small to ask for one) always said `COMMANDS: none`, because it looked for the wrong argument name. A tool call that is not valid JSON is now counted as a `repair` event, like other malformed calls.

## 0.7.4 (2026-11-10)

Found by the harness checks of Amness Evaluation Studio on a local Qwen.

- **Keep the model's thinking across steps (`keepThinking`).** Amness dropped a reply's thinking from the conversation it sends back, so a thinking model saw only its earlier answers and tool calls. On a Terminal-Bench task the model then worked out the same plan five times in a row, at its thinking budget each time, and changed nothing before time ran out. With `keepThinking` on (the model's profile, Preferences or `/settings`: **Keep thinking**, or `amness run --keep-thinking`), each reply's thinking goes back as `reasoning_content`, with `chat_template_kwargs.preserve_thinking` for templates such as Qwen's. When the prompt must shrink, old thinking is dropped first. Off by default; whether it raises the pass rate is not measured yet.
- **Large context windows take larger tool outputs.** The cap on one tool result grows with the window up to 12,000 characters (it stopped at 6,000), so a 6 KB file is read whole with a large window.
- **The `config` line of `amness run --json`** also says whether thinking is kept.

## 0.7.3 (2026-11-10)

- **`amness run --json` says what is in effect.** Its first line is now `{"kind":"config", ...}`: the version, provider and model, server address, context window, step and time limits, the guards on and off, tool choice, thinking budget, extra request fields, where the model's profile came from, the sandbox, plugins and memory. An evaluation (such as [Amness Evaluation Studio](https://github.com/amirsdream/amness-eval-studio)) records it with each run, so results say which features really ran. No key is ever included.

## 0.7.2 (2026-11-09)

Found by running Terminal-Bench tasks with a local Qwen model and reading every run.

- **`amness run` no longer reads its own options as the task.** Some option orders (for example `--trace <file> --max-time <n> -`) left option words in the task text, so the model was asked to do "--trace --max-time -". Every option is now taken out before the task is built.
- **Re-reading a file gets the lines that were cut.** When a file read was longer than the tool-output cap, its middle was cut. A second read of the same file was cut in the same place, and the lines around the cut were then replaced by "already above" markers, so the model could never get the cut lines by reading again. Now the repeated lines become markers first, and only what is left is shortened; only the lines the model really received count as delivered.
- **The system prompt names the working directory.** Models guessed a directory (`cd /home/user`) and lost steps; the environment line now says where commands start.
- **`apply_patch`:** a unified `@@ -2,20 +2,20 @@` header inside a `*** Begin Patch` patch is read as a line hint, not as text to find. When a hunk does not apply, the error now says how many of its lines matched and which line differs (for example a hunk that skips lines), instead of naming its first line and suggesting a re-read.
- **Thinking budget and extra request fields per model.** `thinkingBudget` in the model's profile (Preferences or `/settings`: **Thinking budget**; `amness run --thinking-budget <n>`) caps the thinking tokens of each request on local servers that support it (llama.cpp `thinking_budget_tokens`; `0` turns thinking off). A slow local model that thinks for minutes no longer uses up a timed run. `request` (**Extra request fields**; `amness run --request '<json>'`) adds any fields to every model request, such as sampling settings or `chat_template_kwargs`.
- **Terminal-Bench adapter:** Node and Amness are installed once on the host into a cached bundle that each task container unpacks, with no network (`--ak runtime=off` for the old way); new options `thinking_budget` and `request`. For long evaluations see [Amness Evaluation Studio](https://github.com/amirsdream/amness-eval-studio).

## 0.7.1 (2026-11-09)

- **Docker sandbox engine on Windows.** Docker on Windows runs Linux containers, which cannot use a `C:\` path, so the project is now mounted at `/workspace` there (on macOS and Linux it stays at the same path). Everything else is as in 0.7.0.

## 0.7.0 (2026-11-09)

- **Preferences stays open when a setting opens its own view.** In the desktop app, **Manage…** (keys and servers) and the **Show…** buttons (plugins, hooks, skills, memory, permissions…) closed Preferences and ran in the chat, so your unapplied changes were lost and you could not get back. Now a dialog they open (the provider list, a key prompt) appears above Preferences; finishing or cancelling it brings you back to the same tab with your changes kept and the values refreshed. What a button prints appears under it. One Esc closes only the dialog, not Preferences too. In the terminal, `/settings` also stays in the same group after such a button.
- **`amness tune` v2.** `--models` tunes several models on their own (saved servers, `provider/model`, or model ids) and writes each change only into the profile of the models it held up for. More candidates: every guard except secret masking, `--steps` (step limits), `--tool-choice`. Each change states a prediction and the log says whether it came true. Every run is recorded in `.amness/tune/`. Fixed: writing the tuned profile replaced the whole `profile.json`; it now merges into the model's entry.
- **Sandbox engines.** The sandbox engine is now a choice: `auto` (Seatbelt or Bubblewrap, as before), `docker` (a throwaway container per command; the project mounted at the same path, `.git` read-only, no network in strict mode; optional gVisor runtime `runsc`), or an engine a plugin adds (`sandbox` field). `/set sandboxEngine`, `sandboxImage`, `sandboxRuntime`, `amness run --sandbox-engine`.
- **Dual-LLM mode for untrusted content.** With `/set quarantine on` (or `amness run --quarantine`), web pages and MCP results are read first by a separate model call with no tools; the agent sees only its digest, so instructions hidden in the content cannot reach it. Off by default (an extra call per untrusted result). Plugins can supply their own reader.
- **Best-of-n learns and chooses better.** With `amness run --best-of n`, each attempt after a failure now gets a summary of the failed attempts (files changed, what it said, the verify output) and is told not to repeat them. `--best-of-all` runs all n attempts and picks among the passing ones with a tournament of short model comparisons (groups of three). Plugins can supply their own `select`.

## 0.6.0 (2026-11-09)

- **More settings in one place.** `/settings` and desktop Preferences now also have: tool call every step (per model, saved in its profile), server-side compaction (OpenAI), the system prompt, and in the terminal the side panel, mouse and diff layout. A new **Extend** group opens plugins, hooks, skills, subagents, MCP servers, the model profile and the tool list. The new guards (`pin`, `anchor`, `audit`) are in the Harness group.
- **Your rules survive a context reset.** When the context fills and Amness continues from a handoff note (or after `/compact`), the rules from your later messages ("never edit tests/", "always use pnpm") are now kept word for word after the note, and through later resets too. Before, only the first message was kept and the rest lived only in the summary, which tends to drop such rules. The summary itself now also lists them. New guard `pin` (on by default, switch off with `/harness off pin`).
- **Model profiles: `toolChoice`, all guard names, and `amness run`.** A profile can set `"toolChoice": "required"` (a tool call at every step of a task run, so the server constrains the output to a valid call; for local models that drift into prose). `amness run --tool-choice required` does it for one run. Profiles now accept every guard name (before, `readdelta`, `toolcache` and `coverage` were rejected), and `amness run` now reads the profile, as the chat app does.
- **Unused new files are caught at finish.** When the agent finishes, Amness checks whether new source files it created are imported by anything. If not, the first finish is refused with their names, so the agent wires them up, or says they stand alone. This catches tests that pass while the real code is not connected. New guard `audit` (TypeScript, JavaScript and Python).
- **Searches show related files.** After a `grep`, Amness adds a few lines from its code index for the files with the most hits: which files import them and which tests cover them. The model sees the code's structure without having to call the index tools. New guard `anchor` (on by default).
- **MCP 2026-07-28.** Amness now speaks the current, stateless version of the Model Context Protocol: it asks a new server `server/discover` and sends the protocol fields with every request, with no handshake. Older servers still work: when the probe fails, Amness uses the `initialize` handshake (now version `2025-11-25`). A server that asks for input mid-call gets a clear "not supported yet" error.
- **Thinking from local servers.** llama.cpp, vLLM, DeepSeek and Ollama send the model's thinking beside the answer (`reasoning_content`). Amness now shows it live and counts it (estimated when the server sends no count).
- **`amness run --max-time <seconds>`**: a time limit. Near the end the agent is told to wrap up; at the limit it stops cleanly and the result says `"stopped":"time"`.
- **`amness run --off <guards>` and `--plugin <files>`**: switch guards off and load plugin files for one run (for comparisons). The `--json` result line now also has the token use (sent, cached, received, requests) and a cost estimate.
- **Terminal-Bench 2.0 with Harbor**: `bench/harbor` runs Amness as a Harbor agent (it installs your working tree in each task container), with `run.sh` for named task subsets. See `bench/harbor/README.md`.

## 0.5.2 (2026-11-08)

- **Clearer questions for risky commands.** Before, the approval showed category words such as "recursive/forced delete" or "dangerous system command", sometimes two "⚠" lines that said nearly the same thing, and the desktop app showed the warning twice. Now one line says what this command will do ("Deletes build and everything in it", "Force-pushes feature to origin, replacing the commits there", "Installs left-pad from the internet"), marked ▲ (high) or ● (caution). A second line says whether `/undo` can take it back: yes, partly (not files git ignores, not git history), or no (it reaches another machine, or the folder has no git). The terminal (inline and full screen) and the desktop app show the same two lines; the full-screen view used to leave out "cannot be undone". `sh_start` asks the same way.

## 0.5.0 (2026-11-08)

- **Preferences: Apply, Revert, and up-to-date tabs.** In the desktop app, switching tabs in Preferences showed the values from when it opened, not what you had just changed. Fixed. Every change is now a draft: appearance previews at once, agent settings run on **Apply**, **Revert** undoes everything, and closing with changes left asks first. Changed settings and tabs get a dot.
- **One settings list for both apps.** Desktop Preferences and the new terminal `/settings` page come from one shared list, so they show the same settings and change them with the same code. `/settings` has the same groups and the same Apply. `/set <name> <value>` changes one setting by name.
- **New settings:** Folders and trust (folders outside the project, trusted folders), Context and limits (context window, requests at once, Claude task budget), Search and memory (Tavily key, semantic memory, memory notes), your saved servers in Provider, and permission rules.
- **Saved servers.** Amness now remembers each Ollama or custom server you set up: its address, model and its own key. `/provider` lists them by name, and picking one switches without asking anything. **+ Ollama server…** and **+ Custom OpenAI-compatible server…** set up a new one: the address, an optional key, the model (from the server's own `/v1/models` list) and a name. `/connect` uses, re-keys, edits or forgets a saved server. `/model` on a saved server is remembered with it. `amness run --server <name>` uses one. Each server has its own key slot, so a token is never sent to another server. Your current custom or Ollama setup is saved as a server on the first start. Works the same in the terminal and in the desktop app. Saved servers also keep their place in the list.

## 0.4.2 (2026-11-08)

- **"hi" gets a hello, not a project survey.** In a new session, a greeting made the agent list files and read the project. Three things caused it: the first message carried the project guidance (`AGENTS.md`), skills and memory notes; the nudge guard read "I'll be glad to help" as a stalled task and told the model to use a tool; and the prompts said nothing about greetings. Now small talk ("hi", "thanks", "ok", "how are you") is sent as it is and answered in words. The guidance and notes come with your first real request, so saying hi first loses nothing. The nudge also leaves alone a reply that asks you a question.

## 0.4.1 (2026-11-08)

- **Trust a folder first, as in Claude Code.** The first time you start Amness in a folder, it asks **Do you trust the files in this folder?** Nothing runs before you answer, not even a task given on the command line. **Yes** is saved in `~/.amness/state.json` and covers the folders inside. **No** exits (code 3); in the desktop app, it goes back to the project you had open. In your home folder, Amness warns you. Project hooks, plugins and permission rules are still asked about separately. See [Safety](docs/safety.md#trust-a-folder-before-amness-works-in-it).

## 0.4.0 (2026-11-08)

- **Allow a folder outside the project, as in Claude Code.** Before, the file tools refused any path outside the project. Now Amness asks first (terminal and desktop): **Yes, for this session**, **Yes, and always for this project** or **No**. One yes covers the whole folder. `/dirs` lists, adds (`/dirs add <path>`, or `/add-dir <path>`) and removes allowed folders. `amness run --add-dir <path>` does the same for a headless run. Folders allowed for good are saved in `~/.amness/state.json`, never in the project, so a cloned repository cannot grant itself access. Edits there still ask first in Ask mode. See [Safety](docs/safety.md#allow-a-folder-outside-the-project).

If you never use the desktop app, nothing is downloaded. Set `ELECTRON_SKIP_BINARY_DOWNLOAD=1` to prevent the download; `amness-desktop` then opens in a Chrome/Edge window or your browser.

The window runs the terminal app's own `App` (new `ui: "remote"` mode), so every command, dialog, approval, plugin, MCP server, hook, memory and budget works the same in both, and new features reach both. - **Desktop layout:** thinking shows in the conversation where it happens, open while it forms and folded to one line once the next step starts. The panel has four tiles (context, cost, tokens, cache) and sections that fold. Below 1280/1000 pixels the panel and the sidebar become drawers. The run panel opens the step happening now, in the terminal sidebar too.
- **Desktop preferences and icon:** a Preferences window (⚙, `⌘,`) for appearance (theme, accent, interface and chat text size, code font, density, motion), chat behaviour and the agent settings (model, effort, budget, roles, sandbox, verify, check, reviewers, shell, strategy). Agent settings run the terminal's own commands. Preferences are saved in the config file; before this, the window's choices (folded sections, panels) were lost at every restart because the page's address changes each launch. The app has its own icon in the dock, taskbar and window.
- **Shared side panel:** the sidebar and loop data are computed once (`cli/tui/panel.ts`) for the terminal and the desktop.

- **Input:** `Ctrl+R` searches your earlier messages. `Ctrl+Z`/`Ctrl+Y` undo and redo typing. `Ctrl+G` writes the message in `$VISUAL`/`$EDITOR`. `Ctrl+V` pastes a clipboard image. Pickers now match fuzzily ("gsol" finds "gpt-6.1-sol").
- **Find and navigate (full screen):** `Ctrl+F` finds text in the conversation with live highlights. `Alt+↑`/`Alt+↓` jump between your messages. Clicking a file path in a reply (`src/app.ts:12`) opens it in your editor at that line.

- **Expired key:** when a provider rejects your API key (a 401, or a message that the key is invalid, expired or revoked), the chat asks for a new key, saves it, and sends your message again. A key from an environment variable is not replaced; you are told to update it.
- **DeepSeek cache:** `prompt_cache_hit_tokens` is now read as cached tokens, so the cache figure and the cost are right on DeepSeek.

- **Library:** `governRewrites` rewrites old messages only where the saving beats the cache it loses (`src/rewrite.ts`). Off by default: on 21 replayed sessions it was neither clearly better nor worse.

## 0.1.6 (2026-10-31)

- **Small-window profile:** with a context window of 16,384 tokens or less, Amness sends a much smaller request. A bare "hi" cost 3.4k tokens on a local Qwen (42% of an 8k window); it now costs about 1.3k to 1.5k. The system prompt is a third of the size, the Skills and Memory blocks are compact, and the rarely used tools (memory, skills, subagents, repo map, background shells, patches) stay out of the prompt until the model asks for them with `tool_search`. Nothing changes for large windows.

- **Caching:** four caches that work with any provider. (1) Repeated reads are not run again while nothing changed, and a repeat is answered with a one-line pointer while the first copy is still in the conversation. (2) `amness eval --cache` and `amness run --cache` answer identical model requests from disk, so a rerun costs nothing (trials stay independent). (3) `/plans on` or `--plans` keeps a short plan from each finished task and offers it when a similar task comes in (off until measured). (4) `/cache` shows what was reused, including a vLLM server's prefix-cache hit rate. See [Agent loop](docs/agent-loop.md).

- **Small context windows:** Amness now keeps every request inside the model's context window, so a long session on a small local model (for example a 30B Qwen with an 8k window) no longer dies with "maximum context length". Set the window with `contextWindow` in the config, `AMNESS_CONTEXT_WINDOW`, or `--context-window`; if you set nothing, it is learned from the first overflow error and remembered. As the window fills, old tool output and big tool arguments are shortened first, then a handoff note is written (built from a shrunk copy, with a fallback that needs no model call). The sidebar, footer and `/tokens` show the percentage of this window. `amness run` also gets `--max-steps`. The window is also detected from the server when it reports one (vLLM, LM Studio, llama.cpp, Ollama), so nothing needs to be set. When a long tool result is cut, the marker now says how to read the rest. See [Run a local model](docs/providers.md) and [Agent loop](docs/agent-loop.md).

## 0.1.2 (2026-10-31)

First public version. (0.1.0 and 0.1.1 were staged on npm but never released; they lacked parts of the key store and the bundled Claude SDK below.) A terminal coding agent for OpenAI, Claude and local models, with a full-screen and an inline interface, headless mode, evals, memory, MCP and a library API.

- **Loop and guards:** claims ledger and audit of the finish summary, stagnation detection from test/build output, optional independent reviewer, loop and cycle detection, budget notes and a final report before the token cap, read-only streak check.
- **Safety:** permission rules with a floor that holds in yolo, OS sandbox (macOS Seatbelt, Linux bubblewrap), taint check for commands copied from untrusted text, secrets redaction, shell undo through git snapshots, optional approval reviewer.
- **Tools and context:** apply_patch and multi-edit, background processes, code index (`repo_map`, `find_refs`, `impact`), skills, custom subagents with worktree isolation, hooks, MCP, AGENTS.md loading, image input, optional language-server diagnostics.
- **Cost:** staged context trimming that keeps the provider cache valid, optional cache keep-alive, model routing, per-role models, subagent budget slices.
- **Workflow:** git worktree sessions, `/review`, `/pr`, `/branch`, `amness schedule`, `amness acp`, a GitHub Action.
- **Shell and platform:** the shell is detected per OS (bash, zsh, sh, Git bash, pwsh, Windows PowerShell, cmd), the model is told which one it has, PowerShell and cmd get a safety floor, `/shell` shows what was detected, and `!cmd` runs a command directly.
- **Keys:** the API key is saved in the macOS Keychain, the Linux keyring or Windows DPAPI instead of a plain file (plain file with mode 600 only where there is no store). Keys from environment variables are never saved. In Docker or Kubernetes nothing is written to disk, and `*_API_KEY_FILE` reads Docker secrets. An old plain-text key moves over on the next start.
- **Install:** `npm i -g amness` or `npx amness` gives the `amness` binary and the Claude SDK (an optional dependency) (built to `dist`, Node 22.18 or later). Releases are staged by CI and approved by hand.
- **Measurement:** `amness eval` (paired statistics, ablations, SWE-bench-format suites, leak audit), `amness tune`, trace replay, failure mining.

Known limits: newer features are tested with scripted models but not yet measured on real tasks; Windows has no OS sandbox. See ROADMAP.md.
